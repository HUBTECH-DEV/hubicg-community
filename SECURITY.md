# Security policy

## Supported versions

| Version | Supported |
|---|---|
| Latest tagged minor | Yes |
| Older versions | No, unless announced |

## Reporting a vulnerability

Do not open a public issue. Use GitHub private vulnerability reporting in the
repository Security tab. Include affected version, reproduction steps, impact
and a safe contact method. Never include real prompts, credentials or personal
chat histories.

The project aims to acknowledge a valid report within 5 business days, provide
an initial assessment within 10 business days and coordinate disclosure after a
fix. These are service targets, not guarantees.
